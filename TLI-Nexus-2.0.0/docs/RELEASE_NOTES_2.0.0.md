# TLI Nexus 2.0.0 — Character Intelligence & Build Studio

## Главные изменения

- Автоматические профили по подтверждённым `PlayerId + SeasonId`; имя персонажа используется только как резервный ключ для старых профилей, чтобы не смешивать одноимённых персонажей.
- Настройка раздельно управляет автоматическим созданием профиля и автоматическим выбором активного профиля.
- Character Intelligence восстанавливает подтверждённые поля игрока, числовые характеристики, навыки, таланты, явную экипировку и отдельные снимки сумки/склада. Для каждого раздела сохраняются источник и уровень достоверности.
- Явная экипировка извлекается только из контекстных веток `equipment/equipped/worn` и только при наличии явного ID предмета; слот и аффиксы показываются только при наличии полей в самом сообщении.
- `ResetItemsLayout` и `GetWareHousePage` остаются снимками инвентаря/склада и не переклассифицируются как надетая экипировка.
- История персонажа хранит до 60 содержательных снимков за 365 дней. Повторное наблюдение тех же значений не создаёт новый снимок только из-за другого времени опроса.
- Сравнение снимков показывает изменения характеристик, навыков, талантов, явно подтверждённых предметов, количества и ID аффиксов, если они присутствуют.
- Отчёт Character Health показывает полноту данных, несовпадения PlayerId/сезона, устаревшие данные и пробелы. Процент отражает полноту восстановления, а не силу героя или DPS.
- Анонимизированная диагностика экспортирует схему полей и счётчики без имени/PlayerId/сырых строк/путей к логу.
- Сохранена миграция данных со старых схем 1.x и защита истории персонажа от устаревшей записи Renderer.

## Честные ограничения

- Наличие в логе поля с ID предмета не означает, что в той же записи есть подтверждение надетого слота. Nexus не назначает слот по `PageId`/`SlotId`.
- Аффиксы и значения роллов доступны только при явном присутствии в структуре сообщения. Если клиент их не записал, они остаются неизвестными.
- Снимок сумки/склада не равен экипировке. `PutOn`/`PutOff` остаются наблюдаемыми транзакциями, а не гарантированным полным состоянием всех слотов.
- Анализатор не является полным игровым симулятором DPS. Он проверяет качество/полноту данных, введённые характеристики, личные цели и явно поддерживаемые зависимости.
- Проверка настоящего игрового лога остаётся обязательной пользовательской приёмкой: синтетические fixtures не доказывают полноту всех полей текущей версии клиента.

## Проверки

- Unit/integration тесты CharacterIntel, профилей, истории снимков, diff, privacy report и схемы сохранения.
- Синтетический полный поток через `LiveService.attach()` проверяет повторное чтение файла и восстановление подтверждённых полей.
- Release verifier проверяет Electron 45.2.3, electron-builder 26.18.1, Windows x64 NSIS/portable, ICO 256×256 и локальные `loadFile()` окна без localhost.
- Настоящий UE_game.log не включён в репозиторий; один тест реального файла пропускается без `TLI_REAL_LOG`.
