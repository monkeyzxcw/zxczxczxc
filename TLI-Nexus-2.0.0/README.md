# TLI Nexus 2.4.0

**Настольный игровой компаньон для Torchlight: Infinite.** Nexus ведёт отдельную сессию на каждый запуск игры, считает дроп по картам, автоматически обновляет TLIDB и читает локальный UE_game.log в режиме Read Only. Лаборатория билдов связывает характеристики, навыки, таланты и подтверждённые игровые аффиксы, объясняет найденные расхождения и формирует план улучшений на основе доступных доказательств.

> Nexus — независимый фанатский инструмент, не связанный с XD. Программа не внедряется в игру, не читает память процесса и не отправляет команды клиенту. Главное окно и HUD — локальные Electron-окна через `loadFile()`, localhost-сервер не используется.

## Быстрый запуск Windows

1. Распакуй архив в отдельную папку. Для установки поверх предыдущей версии используй резервную копию.
2. Для сборки установщика на Windows x64 установи Node.js 22.13+.
3. Запусти `build-installer.bat`.
4. После успешной сборки открой `release/TLI-Nexus-2.4.0-Setup-x64.exe` для установки или `release/TLI-Nexus-2.4.0-Portable-x64.exe` для запуска без установки.
5. При первом запуске разреши Nexus прочитать игровой лог. В Torchlight: Infinite включи `ESC → Другое → Enable Log`, затем повторно войди персонажем.
6. Если автопоиск не подключился, выбери активный `UE_game.log` в настройках Nexus.

TLIDB остаётся фанатским справочником: автоматическое обновление не подтверждает сезон/патч и не раскрывает внутренние AffixId/AttrType.

Сборка использует Electron 45.2.3 и electron-builder 26.18.1. Этот архив содержит исходный проект и конфигурацию Windows-сборки. Windows EXE в Linux-среде не собирался и не тестировался; фактическую компиляцию и проверку установщика нужно выполнить на Windows.


## Что нового в 2.4.0 — Полный анализ билда

- В «Анализ персонажа» добавлен полный аудит сохранённой сборки: фактические характеристики из Character Intelligence сверяются с целями, указанными в билде.
- Навыки, поддержки и таланты сравниваются по точным ID из сохранённой сборки и последнего доступного игрового снимка. Текстовые описания без ID не считаются подтверждённым совпадением.
- Явные объекты надетых предметов сопоставляются с локальными FModel DataTable по точному ID. Импортированные строки позволяют раскрывать название предмета, атрибут, тир и диапазон аффикса.
- Для аффикса рассчитывается положение ролла внутри диапазона только при точном совпадении ID и однозначном числовом значении. Ролл в нижней четверти показывается как повод сравнить предмет, а не как автоматический приговор.
- План улучшений сортируется по разрывам между фактическими и личными целевыми характеристиками, несовпадению ID навыков/талантов и подтверждённым низким роллам.
- Частичные PutOn/PutOff и снимки сумки отдельно обозначаются как неполные данные и не выдаются за весь комплект экипировки.
- Покрытие данных не называется силой билда. Nexus не придумывает DPS, мультипликаторы, мета-рейтинг и взаимодействия поддержки/талантов, если текущие игровые источники не подтверждают нужные формулы и связи.

## Что нового в 2.3.0 — Автоматическое обновление TLIDB

- При первом запуске или устаревшем локальном кэше Nexus автоматически загружает 38 страниц аффиксов TLIDB.
- Дальше база обновляется в фоне по расписанию. По умолчанию — раз в 24 часа; доступны интервалы 6, 12, 24, 48 часов и 7 дней.
- Автоматическая синхронизация работает в основном процессе приложения и не зависит от открытого окна настроек.
- При ошибках сети или ограничении запросов сохраняются прежние записи недоступных страниц; удачно загруженные страницы обновляются.
- После ошибки выполняется повторная попытка примерно через час. Ручная кнопка обновления также остаётся доступна.
- В настройках отображаются состояние синхронизации, интервал и последняя ошибка.

## Учёт игрового запуска и дропа по картам

- Общая сессия начинается при обнаружении запуска Torchlight: Infinite и заканчивается после остановки игрового процесса.
- Переподключение или ротация `UE_game.log` больше не сбрасывает время, FE и предметы за игровой запуск.
- Перезапуск только Nexus не начинает новую сессию, если Torchlight всё ещё работает: состояние восстанавливается по PID и времени создания процесса. Завершённая во время закрытого Nexus игра закрывает старую запись после проверки процесса.
- Вход в новую инстанс-карту открывает отдельный забег карты. Переход в город завершает его, но сохраняет результат последней карты и не обнуляет общие показатели запуска.
- В HUD раздельно показываются FE за весь запуск и FE за текущую/последнюю карту; в расширенном режиме виден список предметов по каждому итогу.
- В истории фарма один запуск клиента хранится как одна сессия, а внутри неё сохраняются завершённые карты и их добыча.
- Известные городские/социальные зоны (Town, City, Hub, Stronghold и похожие) не считаются картами. Остальные области из `Content/Art/Maps` учитываются как отдельные инстансы; переходы без подтверждённого пути не запускают новую карту.
## Что нового в 2.2.0 — Игровые ресурсы и данные предметов

- Импорт локальных FModel / Unreal JSON-экспортов с поиском DataTable, RowMap и Rows.
- Сопоставление ID наблюдаемых предметов и аффиксов с импортированными строками игровых таблиц.
- Расширенное сохранение сырых данных предметов: уровень, редкость, качество, усиление, слот, ID аффиксов и пути источников.
- В Настройки добавлена отдельная панель «Игровая база: предметы и аффиксы».
- Отдельные enum-таблицы позволяют разрешать AttrType, слоты, редкость и качество; локализационные строки сопоставляются по точным ключам.
- Отдельно индексируются `AffixAttrType`, атрибуты персонажа, слоты, редкость и качество; сырые коды разрешаются по типу таблицы.
- Неизвестные игровые enum, ID и диапазоны не подменяются предположениями.

**Важно по текущему экспорту:** приложенный архив содержит художественные ресурсы экипировки и имена типов из DefaultGame.json, но не сами таблицы значений аффиксов. Смотри [документацию по извлечению игровых ресурсов](docs/GAME_RESOURCE_EXTRACTION.md), чтобы экспортировать недостающие DataTable из FModel.

## Что нового в 2.1.0 — Интеллект экипировки

- Анализ явно наблюдаемых объектов экипировки из Character Intelligence.
- Индивидуальные приоритеты характеристик для каждой сборки внутри профиля: точный ключ поля, пользовательская подпись, вес 1–5 и направление сравнения.
- Сравнение двух предметов по совпадающим ключам и только по совместимым числовым значениям.
- Выявление отсутствующих в доступных данных приоритетных полей и объяснение ограничений.
- Не рассчитывается DPS или универсальный рейтинг качества предмета. Процент отражает только долю обнаруженных полей среди твоих приоритетов.

## Что нового в 2.0.0

### Character Intelligence 2.0

- Автоматический профиль на основе подтверждённых `PlayerId + SeasonId`; одноимённые персонажи и разные сезоны не смешиваются.
- Независимые настройки автоматического создания профиля и автоматического выбора активного профиля.
- Восстановление личности, явных характеристик, навыков, талантов, отдельных снимков сумки/склада и тех элементов экипировки, которые действительно присутствуют в соответствующих ветках лога.
- Каждое поле хранит исходный ключ/путь, действие/socket-контекст, время и уровень подтверждения.
- Явная экипировка выделена отдельно от `PutOn`/`PutOff` и отдельно от сумки/склада.
- История до 60 содержательных снимков персонажа за 365 дней, сравнение характеристик, навыков, талантов, экипировки, количества и явных ID аффиксов.
- Отчёт полноты данных и экспорт анонимизированной диагностики. Процент полноты не является рейтингом силы персонажа.

### Остальные модули

- **Профили:** отдельные герои, специализации, сезоны, уровни, билды и история снимков.
- **Экономика:** локальная история цен, ценовые графики и целевые уведомления.
- **Фарм:** чистая прибыль, FE/час, медиана, P25–P75, MAD, коэффициент вариации, стабильность и фильтр по персонажу.
- **Лаборатория билдов:** создание, импорт/экспорт кода Nexus, сравнение характеристик, экипировки по явно указанным слотам, навыков, талантов и затрат.
- **HUD:** компактный/расширенный режим, прозрачность, масштаб, положение, pin/unpin, click-through и аварийные комбинации.
- **Уведомления:** ценный дроп, рынок, звук и анимации.
- **Локальная база предметов:** поиск по ID/названию; изображения подгружаются по требованию и кэшируются.
- **Тактики и заметки:** персональная база по активности, боссам и фарму.
- **Резервные копии:** экспорт/импорт профилей, билдов, ценовой истории, сессий и заметок.

## Как читать результаты Character Intelligence

У каждого раздела есть статус:

- `Наблюдается` — в игровом сообщении найдено подходящее поле.
- `Частично` — обнаружены только отдельные транзакции или неполный снимок.
- `Отсутствует` — подходящее поле не найдено в просканированном диапазоне лога.
- `Устарело` — последнее подтверждённое наблюдение старше порога свежести.

**Нельзя путать разные источники:**

- `GetPlayerData` — личность и те характеристики/умения, которые сервер действительно прислал.
- `ResetItemsLayout` / `GetWareHousePage` — снимки сумки или склада, не экипировка.
- `PutOn` / `PutOff` вместе с BagMgr delta — наблюдаемые изменения инвентаря; это не обязательно полный текущий набор слотов.
- Явные ветки `equipment/equipped/worn` — могут давать предмет, сырой слот и аффиксы, но только если соответствующие поля реально есть в сообщении.

Nexus не выводит слот из `PageId`/`SlotId`, не превращает случайное поле аффикса в характеристику персонажа и не заполняет неизвестные значения догадками.

## Ограничения 2.0.0

- Некоторые версии клиента могут не писать полный снимок экипировки, все аффиксы, роллы или параметры героя. В таком случае Nexus покажет отсутствие/частичность данных.
- `PutOn`/`PutOff` дают только наблюдаемые изменения; если Nexus не работал в момент события, прошлое состояние может быть неизвестно.
- Полный математический DPS-симулятор, точное моделирование боссов и полностью автоматическая мета-рекомендация не входят в этот релиз.
- Иконки не упакованы бинарно: при первом показе предмета нужен доступ к источнику CDN. Цены — оценка, а не гарантированная цена продажи.
- Автоматический updater и цифровая подпись установщика не включены.

## Горячие клавиши

- `Ctrl + Shift + O` — показать/скрыть HUD.
- `Ctrl + Shift + N` — открыть Dashboard.
- `Ctrl + Shift + M` — переключить сквозной клик.
- `Ctrl + Alt + M` — принудительно выключить сквозной клик.
- `Ctrl + Shift + P` — закрепить/открепить HUD поверх окон.

Аварийные комбинации для выхода из сквозного клика продолжают работать, даже если обычные горячие клавиши отключены.

## Данные и приватность

Профили, снимки персонажа, билды, история сессий, ценовые снимки, настройки и кэш хранятся локально в папке данных Electron. Анонимизированная диагностика не содержит имя персонажа, PlayerId, сырой текст лога и путь к файлу. Для цен и иконок выполняются исходящие HTTPS-запросы к соответствующим источникам. Сам игровой лог на сервер Nexus не отправляется.

## Сборка и тесты

```bash
npm install
npm run release:check
npm run dist:win
```

Перед принятием версии проверь `docs/USER_ACCEPTANCE_CHECKLIST.md` на Windows с настоящей игрой. Тест с реальным логом пропускается без `TLI_REAL_LOG`; синтетические тесты не доказывают полноту структуры конкретной версии игры.


## Внешняя база аффиксов TLIDB (2.3.0)

В Настройках можно автоматически загрузить и обновлять открытые страницы TLIDB по 38 типам экипировки. По умолчанию синхронизация выполняется раз в 24 часа; доступны интервалы 6, 12, 24, 48 часов и 7 дней. Ручная кнопка синхронизации также доступна. Можно искать базовые, коррозионные и крафтовые аффиксы. В выдаче показываются тир, исходный диапазон, минимальный уровень предмета, вес, библиотека аффиксов и ссылка на страницу-источник.

Кэш TLIDB хранится отдельно на компьютере пользователя. Он не включается в установщик и не загружается на сервер Nexus. На самих страницах нет надёжной метки сезона/патча, поэтому версия помечается как непроверенная. Внутренние AffixId и AttrType не угадываются и по текстовому названию не подменяются. Для точных игровых ID по-прежнему нужен импорт подтверждённых FModel/Unreal DataTable.
